# 三阶段实施计划调整建议 V1.1

> 状态：建议稿，待团队与教师确认。日期：2026-11-09。原三阶段计划 V1.0 保留不变。下列“计划”均不代表已完成；实际结果以代码、日志、审核记录和教师最新提交要求为准。

## 1. 调整依据

延续 V1.0 的 NEU-CLS 六分类、ResNet18 C0→C1 与 Streamlit 技术路线，建议增加“分类类别→可追溯工艺知识→质量人员核查”的应用层。数据集中没有生产参数与经确认的根因标签，因此这层只能提供候选线索。第一阶段已有数据工程和 C0 验证记录；知识关联尚未实现。

## 2. 阶段安排

| 阶段 | 计划时间/节点 | 建议工作与可审查产物 |
| --- | --- | --- |
| 第一阶段 | 截至 2026-11-10 08:00 | 保留已核实的数据质量、固定划分、C0 训练与验证结果；论文写明知识模块方案与证据边界，不将方案写成实现 |
| 第二阶段 | 2026-11-10 至 2026-12-01 08:00 | 完成 C1 部分微调及同划分验证对照；完成单图预测接口、Streamlit 展示与结构化知识表初版；每条知识保留原文定位、工况、审核状态；演示类别、输出分布、候选线索与来源 |
| 第三阶段 | 2026-12-01 至 2026-12-22 08:00 | 在模型选择冻结后使用保留测试集作最终评价；复核分类误差、知识条目、六类覆盖与异常路径；记录人工审核意见，更新最终论文和演示材料 |

第二阶段若时间不足，先保证 C0/单图预测可复现、已审核知识条目可展示和边界提示正确，再处理扩展分析；不得把未审核内容伪装成已证实机制。报告提交方式、文件命名与截止安排如有教师新通知，以最新通知为准。

## 3. 三人分工建议

| 角色（待填写负责人） | 第二阶段主责 | 第三阶段主责 | 交叉审核 |
| --- | --- | --- | --- |
| A：数据与来源 | 维护固定划分、类别映射和知识来源清单，录入工艺文献条目 | 核对知识覆盖、引用定位和数据边界 | 审核 B 的类别查询与 C 的数据表述 |
| B：模型与集成 | C1 训练、与 C0 的同条件比较、推理接口和异常处理 | 保留测试集最终评价、复现检查、系统功能测试 | 审核 A 的类别映射及条目检索 |
| C：界面与论文 | Streamlit 展示、证据卡片与提示文案、第二阶段报告 | 用户路径检查、知识审阅记录汇总、最终论文 | 审核 A 的工艺表述和 B 的实验结论 |

知识条目实行“录入者之外至少一人复核”；工艺专业性不足或来源相互矛盾时保留争议状态，不直接发布为确定性结论。上述角色是工作建议，成员姓名与责任须由团队确认。

## 4. 验收门槛与证据

- **分类模块：** C0/C1 使用同一固定划分和指标；保留每轮日志、配置、最佳权重和逐类验证结果。测试集只在最终选择完成后用于一次性评价。
- **知识模块：** 六类都记录覆盖状态；每个拟展示条目须有可定位原文、来源链接或 DOI、适用条件、审阅人与状态；人工核对类别映射与条目关联，不设虚构的“根因诊断准确率”。
- **异常路径：** 对输入无效、推理失败、类别不确定、来源缺失或失效、知识未审核等情况提供可理解的提示，不输出确定性生产指令。
- **报告与演示：** 分别标注已完成、进行中和计划内容；由 A/B/C 交叉核对数据、模型结果、知识引用及界面截图。教师最新 Overleaf 要求优先于旧文件管理建议。

本调整不改变原 V1.0 对数据库、工业相机、工业实时部署和自动工艺优化的排除范围，也不提出大模型或 RAG 依赖。
