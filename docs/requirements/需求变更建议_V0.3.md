# 钢材表面缺陷分类项目：需求变更建议 V0.3

> 状态：建议稿，待三人小组和课程教师确认。日期：2026-11-09。原《需求说明与验收标准 V0.2》仍是当前基线；本稿不表示新增功能已经实现。

## 1. 变更缘由与目标

V0.2 已要求 NEU-CLS 六分类、C0/C1 比较及单图演示，输出主要为类别和六类模型分数。建议增加一个与分类模块分离的**工艺知识辅助分析模块**：使用预测类别查询经人工审核的文献知识，向质量管理人员展示可能涉及的工序、候选机制、适用条件、资料出处和后续核查方向。其结果是待核查线索，不是单图根因诊断或工艺参数调整建议。

## 2. 建议新增功能要求

| 编号 | 建议要求 | 边界 |
| --- | --- | --- |
| FR-K01 | 建立结构化知识表，以现有六类固定类别映射为索引 | 不改动原始图像、划分或已训练权重；无需数据库 |
| FR-K02 | 每条知识记录类别、工序、候选机制、材料/工况范围、原文证据与页码、DOI/稳定链接、证据类型、反例、核查建议、审核人与状态 | 分类识别论文不能单独充当工艺成因的直接证据 |
| FR-K03 | 仅展示已核实且已复核的条目；同时显示模型类别及输出分布、来源和“仅供核查”说明 | Softmax 值不是经过校准的正确率 |
| FR-K04 | 未审核、来源失效、类别不匹配或证据不足时显示原因及“暂无可靠工艺关联” | 不以猜测补齐六类机制 |
| FR-K05 | 输入异常、模型推理失败或输出不确定时引导人工复核，不自动给出确定性根因 | 不执行生产工艺调整 |

## 3. 知识来源与审核规则

优先使用钢材生产、材料表征和工艺案例的原始研究或专业工艺资料；综述可用于检索背景，但条目中的具体机制须能追溯到支持该机制的原文。记录适用材料和工况，不能将某厂案例泛化为 NEU-CLS 图像的真实成因。建议一人录入、一人交叉审核；保留审核日期、争议和修订记录。Pa 等证据不足的类别应明确标为待核实。

## 4. 建议验收方式

1. **知识覆盖：** 六个类别都有覆盖状态（已核实条目、弱关联、暂无证据）；覆盖率与已审核条目数分别记录，不能把“有条目”当作“有确定机制”。
2. **来源可追溯：** 抽查每条展示文本能否回到原文、页码或章节、DOI/链接及适用条件；链接失效时不得继续作为已核实来源。
3. **类别关联：** 对照固定类别映射人工核对六类查询结果，检查 In/Sc 等易混类别不会串用知识条目。
4. **异常处理：** 测试缺失来源、未审核条目、无关联类别、非预期输入、推理失败和不确定输出时的提示与降级行为。
5. **独立评价：** 分类仍使用保留测试集的 Accuracy、Macro-F1、逐类指标和混淆矩阵；知识模块以人工内容审核及功能测试验收。NEU-CLS 不含真实工艺根因标签，不能计算所谓“根因诊断准确率”。

## 5. 范围及团队建议

第二阶段建议实现结构化知识表、查询逻辑和 Streamlit 展示原型，并完成 C1 与 C0 的公平比较；第三阶段验证知识内容、异常路径、可追溯性和分类最终结果。暂不增加独立数据库、大模型、RAG、工业相机接入、实时控制或自动参数优化。具体分工可按 V1.1 建议稿由三人确认。
